# Decisão 48: Texto extra das notas de release fica no workflow, CHANGELOG só técnico

- **Data:** 2026-09-17
- **Status:** Aprovada

Padronização das notas de release (pedido do responsável do projeto ao cortar a v1.8.0): o `CHANGELOG.md` continua só com o conteúdo técnico (formato Keep a Changelog, decisão 27/31), sem propaganda — quem lê o arquivo no repositório não precisa disso. O texto extra (introdução breve do projeto, CTA de doação, instruções de instalação por SO) foi pra dentro do **workflow** (`.github/workflows/release.yml`, job `draft-release`), que já envolve a seção do `CHANGELOG.md` extraída com esse conteúdo fixo antes de criar o rascunho do GitHub Release — padronizado automaticamente pra **todo** release futuro, sem esforço manual extra a cada tag
