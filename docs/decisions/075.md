# Decisão 75: Leva 0: backup e restauração em zip da pasta de dados, menu Ações no Histórico

- **Data:** 2026-09-22
- **Status:** Aprovada

Leva 0 do plano de evolução (ver [roadmap.md](../roadmap/plano-1-historico.md#leva-0--rede-de-proteção-antes-de-mexer-no-modelo-de-dados)): **(1) Backup e restauração** (`data/BackupRepository`, expect/actual como os outros repositórios). Backup é um `.zip` da pasta de dados inteira (`appDataDir()`, varredura recursiva) em vez de uma lista fixa de arquivos — assim arquivo novo criado no futuro entra no backup sozinho, sem ninguém lembrar de atualizar a lista. Na raiz do zip vai um `3dreport-backup.json` (app/versão/data), que **não** é extraído junto com os dados: serve só pra restauração reconhecer que o arquivo escolhido é um backup do 3DReport e não um `.zip` qualquer. Montado com a API de JSON em runtime (`buildJsonObject`), não com uma classe `@Serializable`, porque o módulo `composeApp` não aplica o plugin de serialização (só o `core` aplica) — evita mexer na configuração de build só por causa de um manifesto de 3 campos. **Restauração é transacional:** extrai numa pasta irmã temporária, valida, só então renomeia a pasta de dados atual pra `.3dreport-anterior-<data>` e põe a nova no lugar; qualquer falha antes disso não toca em nada, e falha na troca final desfaz o passo anterior. Os dados substituídos **não são apagados** (viram a pasta `-anterior-`), pra dar como desfazer no braço quem restaurar o arquivo errado — limpar isso fica a cargo do usuário, de propósito. Entradas do zip têm o caminho validado contra "zip slip" (`../..` gravaria fora da pasta de dados). **O app se fecha ao final da restauração** (`platform/exitApp`, novo): os repositórios carregam os dados em memória na inicialização, então continuar aberto faria a próxima gravação sobrescrever o que acabou de ser restaurado com o estado antigo — fechar é seguro porque toda alteração já é gravada em disco na hora. A alternativa (dar um `reload()` a cada repositório) foi descartada por ser mais superfície de erro justamente onde o custo de errar é perder os dados do negócio. **(2) Menu "⋮ Ações" na linha do Histórico:** a lista tinha chegado a 8 botões de texto lado a lado; ficam visíveis "Exportar PDF", "Copiar" e "Editar", e vão pro menu "Duplicar", "Configurações de impressão", "Baixar foto", "Baixar STL" e "Excluir" — mesmo padrão que os cards do Kanban já usavam (decisão 70)
