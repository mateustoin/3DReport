# Decisão 58: Troca para JFileChooser com filtro de extensão (revertida na 59)

- **Data:** 2026-09-20
- **Status:** Aprovada

Correção da correção (decisão 57 não resolveu, reportado pelo responsável do projeto): o wildcard `*.gcode;*.gco;*.g` definido em `FileDialog.file` não virou um filtro de tipo no diálogo do Windows — foi parar na caixa de texto do nome do arquivo, sem filtrar a lista. Diagnóstico revisado: o `java.awt.FileDialog` no Windows moderno não expõe um combo de "tipo de arquivo" filtrável por API Java de forma confiável, nem por `filenameFilter` (decisão 55) nem pelo wildcard em `file` (decisão 57) — é uma limitação do próprio peer nativo, não dá pra contornar mantendo esse componente. Trocado por `javax.swing.JFileChooser` com `FileNameExtensionFilter` (`isAcceptAllFileFilterUsed = false`, sem opção "todos os arquivos") nos dois diálogos de escolher arquivo do app — G-code (`pickGCodeFile`, extensões `gcode`/`gco`/`g`) e foto (`pickImageFile`, extensões `png`/`jpg`/`jpeg`/`gif`/`bmp`/`webp`, pedido explícito de aplicar a mesma correção ali também). `JFileChooser` é um diálogo Swing (não o diálogo nativo do SO) — visual ligeiramente diferente do Explorer do Windows, mas com filtro de tipo que funciona de fato em qualquer plataforma, o que resolve o problema reportado
