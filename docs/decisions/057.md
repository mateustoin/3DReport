# Decisão 57: Filtro de extensão do diálogo de G-code via wildcard em FileDialog.file no Windows

- **Data:** 2026-09-20
- **Status:** Aprovada

Correção (reportada pelo responsável do projeto): o diálogo de "Preencher a partir do G-code" mostrava todos os arquivos no Windows, não só `.gcode`/`.gco`/`.g` — apesar de `FileDialog.filenameFilter` já estar configurado desde a decisão 55. Causa: o peer nativo do `java.awt.FileDialog` no Windows não chama o `FilenameFilter` do Java de volta (limitação antiga e conhecida do AWT nessa plataforma, sem fix da JDK) — o filtro só funciona de fato em plataformas cujo peer honra esse callback (ex. GTK no Linux). Corrigido definindo `FileDialog.file` com o padrão wildcard (`*.gcode;*.gco;*.g`) antes de abrir o diálogo, que o Windows usa como filtro de fato — mantido o `filenameFilter` também, sem custo, pra continuar funcionando nas plataformas que o respeitam. Mesma causa provavelmente afeta o diálogo de escolher foto (`pickImageFile`), não corrigido aqui por não ter sido reportado — mesma correção se aplicaria lá se algum dia incomodar
