# Decisão 61: Anexar STL ao histórico antes do visualizador, que é um rasterizador no Canvas

- **Data:** 2026-09-21
- **Status:** Aprovada

Fase 1 do roadmap (visualização de STL), duas decisões juntas: **(1)** anexar/guardar o STL no histórico entra **antes e separado** do parser/visualizador (pedido do responsável do projeto) — organização de arquivo de modelo já é valor real por si só (recuperar o STL de uma venda antiga pra vender de novo pra outro cliente), sem depender do visualizador estar pronto. Implementado exatamente como o `photo`/`sourceLink` já funcionam: `platform/pickStlFile` (mesmo padrão `FileDialog` nativo de `pickImageFile`/`pickGCodeFile`), `SavedQuote.stlFileName`, persistido em `~/.3dreport/models/`, com "Baixar STL" no Histórico e exclusão em cascata junto do orçamento — uso só interno, nunca exportado. **Ideia registrada pro futuro** (não implementada agora): também aceitar o `.3mf` do projeto do fatiador, opcional, pra recuperar as configurações de fatiamento usadas (não só a geometria) numa venda repetida da mesma peça. **(2)** Decisão técnica do visualizador 3D (rendering), pendente desde que a Fase 1 foi escrita: entre renderização nativa via OpenGL (LWJGL), WebView embutido + three.js, ou um rasterizador simples desenhado no `Canvas` do Compose — escolhido o **rasterizador simples** (sombreamento plano por triângulo via produto escalar normal·luz, ordenação pintor pra profundidade, câmera orbital por arrasto/scroll). Critério: entrega tudo que foi pedido funcionalmente (orbitar, zoom, mudar ângulo, exportar como foto) sem somar nenhuma dependência nova nem inflar o instalador — WebView+three.js somaria uma engine de navegador embarcada (100+ MB por SO via JCEF, incompatível com o perfil leve do app); OpenGL nativo exigiria misturar um componente pesado do AWT dentro da janela do Compose, combinação com histórico de problemas de sobreposição entre os dois. Trade-off aceito: sombreamento mais simples (sem gradiente suave por pixel) e desempenho pode cair em malhas muito densas — aceitável pro caso de uso (produtos de venda, não scans 3D de altíssimo detalhe); dá pra evoluir pra OpenGL depois se a qualidade virar um problema real na prática
